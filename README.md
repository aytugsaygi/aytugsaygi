## 🚀 Featured Projects

### 🚧 Automatic Barrier Gate Control Software

  <img src="https://img.shields.io/badge/Language-C-A8B9CC?style=flat-square&logo=c&logoColor=black" alt="Language: C" height="22" /> <img src="https://img.shields.io/badge/Domain-Control%20Software-0F172A?style=flat-square" alt="Domain: Control Software" height="22" /> <img src="https://img.shields.io/badge/Optima%20Engineering%20Inc.-Jun%202025%20%E2%80%93%20Jul%202025-38BDF8?style=flat-square" alt="Optima Engineering Inc., Jun 2025 to Jul 2025" height="22" />

> Built during my internship at **Optima Engineering Inc.** This is a **company-confidential product**, so the source code is not public and the description below stays at the design level.

**What I built**

I developed the **end-to-end control logic for an automatic barrier gate product from scratch in C**. I defined the open/close commands, the sensor triggers and the fault-state behaviour, which made the system operate reliably and predictably in the field.

**How I approached it — three stages**

| Stage | What it covered |
| :--- | :--- |
| **1. Core control functions** | Sensor reading, trigger conditions and motor drive commands |
| **2. Hardware deployment** | Loading the software onto the control board and verifying it on the device |
| **3. Iterative debugging** | Condition tests and output checks, repeated until behaviour was stable |

**Problems I solved**

The hardest part was the class of faults that looked identical from the outside: **timing**, **sensor-response** and **state-transition** errors. I resolved them by:

- **Separating software-related issues from hardware-related ones**, so I was never debugging the wrong layer.
- **Splitting the control logic into small, testable functions**, which let me isolate a fault to a single function instead of the whole flow.

This sped up debugging considerably and made the system behave consistently across scenarios.

**What I took away** — writing control logic that is testable by construction, and disciplined fault isolation between software and hardware.

### 💥 Collision Detection and Damage Diagnosis System

  <img src="https://img.shields.io/badge/Tool-LabVIEW-FFDB00?style=flat-square&logo=labview&logoColor=black" alt="Tool: LabVIEW" height="22" /> <img src="https://img.shields.io/badge/Domain-Sensor%20Integration-0F172A?style=flat-square" alt="Domain: Sensor Integration" height="22" /> <img src="https://img.shields.io/badge/%C3%87ankaya%20University-Team%20Project-38BDF8?style=flat-square" alt="Cankaya University, team project" height="22" />

**What we built**

Together with my teammates I developed a **sensor-based collision avoidance and damage diagnosis system in LabVIEW** — it both warns before a collision and classifies how bad the impact was once it happens.

**Sensor architecture**

| Purpose | Sensors | Output |
| :--- | :--- | :--- |
| **Distance tracking** | Infrared + sonar | Proximity to obstacles, used for collision avoidance |
| **Impact assessment** | Piezoelectric + strain gauge | Collision severity classified as **normal**, **minor** or **critical** |

**Calibration and validation**

- We **calibrated the system with our own measurements** rather than relying on datasheet values.
- We then **analysed its performance on the provided data sets** to check that the severity classification held up.

**Signal processing and interface**

- Designed a **filter to clean the raw sensor data** before it reached the classification logic.
- Built a **LabVIEW interface with LED indicators** for real-time monitoring of distance and impact state.

**What I took away** — hands-on experience in **sensor integration**, **signal processing** and **system modelling**.

### 🅿️ Vehicle Assignment Simulation for Parking Management

  <img src="https://img.shields.io/badge/Tool-MATLAB-0076A8?style=flat-square" alt="Tool: MATLAB" height="22" /> <img src="https://img.shields.io/badge/Domain-Constrained%20Optimisation-0F172A?style=flat-square" alt="Domain: Constrained Optimisation" height="22" /> <img src="https://img.shields.io/badge/%C3%87ankaya%20University-Individual%20Project-38BDF8?style=flat-square" alt="Cankaya University, individual project" height="22" />

**What I built**

A **rule-based simulation in MATLAB** that assigns every vehicle entering the campus to the most suitable parking area.

**The model**

I modelled **five parking areas**, each with a different capacity and its own rules:

- **User type** (e.g. staff vs student)
- **Vehicle size**
- **Electric and accessible parking** reservations

**The assignment logic**

Each incoming vehicle is first **filtered against these constraints**, and then assigned to the **lowest-cost eligible area**. The cost function combines three criteria:

| Criterion | Why it matters |
| :--- | :--- |
| **Driving distance** | Time and congestion getting to the area |
| **Walking distance** | How far the driver walks after parking |
| **Penalty scores** | Discourages assignments that technically fit but are undesirable |

**Testing**

I ran the algorithm under **two traffic scenarios of 100 vehicles each**, comparing **access times**, **walking distances** and **rejection rates** between them.

**What I took away** — practical experience in **constrained optimisation** and **multi-criteria cost function design**.
